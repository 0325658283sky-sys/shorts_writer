# 흐름 재설계 — 넣고 바로 변환 (2026-10)

**상태:** 설계 확정. 구현 전.
**날짜:** 2026-10-12
**관련 문서:** [PROJECT_STATUS.md](PROJECT_STATUS.md), [WIZARD_DESIGN.md](WIZARD_DESIGN.md) (블로그 경로만 유효), [REMOTION_EVAL.md](REMOTION_EVAL.md), [DESIGN_SYSTEM_UNIFICATION.md](DESIGN_SYSTEM_UNIFICATION.md)

피카클립(fikaclip.com)을 실제로 사용해 분해한 뒤, New Cut의 사용자 흐름과 템플릿 구조를 다시 잡은 결과다. 이 문서가 **영상 클리핑 경로의 UX·템플릿에 관한 최신 결정**이며, 아래 "번복된 결정"에 적힌 두 건은 이 문서가 대체한다.

## 1. 번복된 결정 (중요)

`PROJECT_STATUS.md`의 "Decisions already made"에 적힌 아래 두 건은 더 이상 유효하지 않다.

| 이전 결정 | 새 결정 | 이유 |
|---|---|---|
| **영상 클리핑은 FFmpeg 유지, Remotion 레이아웃 패리티를 추구하지 않는다** | **두 경로를 Remotion 단일 렌더러로 통합한다** | ASS 자막으로는 모션 자막(팝·바운스·카라오케 등)이 원리적으로 불가능. 템플릿 품질이 제품 체감 품질을 좌우하는데 FFmpeg 경로에서는 그 품질이 나오지 않는다. |
| **UI는 SuperShorts의 스텝 위자드 IA를 따른다** | **영상 클리핑 경로는 위자드를 쓰지 않는다.** 넣고 바로 변환한다 | 처음 쓰는 사용자는 결과를 보기 전까지 장르·길이·템플릿을 고를 근거가 없다. 전부 기본값으로 넘기므로 단계만 늘어난다. 블로그 경로의 위자드(W1~W5)는 그대로 둔다 — 보드·이미지 선택처럼 사용자 입력이 실제로 필요한 단계가 있기 때문. |

구현된 위자드 코드(W1~W5)는 **블로그 경로 전용**으로 범위를 좁힌다. 삭제하지 말 것. 영상 클리핑 경로에 재사용하지도 말 것.

## 2. 새 사용자 흐름

```text
링크/파일 넣기            ← 설정은 접힌 패널 하나, 펼치지 않아도 됨
  → 변환                  ← 장르·길이는 자동 추론
  → 변환 중 (진행 단계 표시, 추론한 장르 미리 고지)
  → 결과: 클립 6~8개, 점수순
       · 판단 근거 고지 + "다르게 다시 찾기"(크레딧 재차감)
       · 템플릿 교체(무료, 재렌더만)
  → 클립 선택 → 편집 → 내보내기
```

소스는 4종을 **하나의 입력**으로 받고 종류를 자동 판별한다 — 유튜브 링크, 블로그·뉴스 글 링크, 상품 페이지 링크, MP4 파일. 네 종류 모두 백엔드에 이미 구현되어 있다(`video_service.py`, `blog_service.py`, `product_service.py`). 입력 UI만 합치면 된다.

탭으로 나누지 않는다. 사용자가 붙여넣기 전에 "내 링크가 어느 탭인지" 판단하게 만들 이유가 없다.

## 3. 설정의 분류 — 이 문서에서 가장 중요한 규칙

설정에는 **자르는 위치를 바꾸는 것**과 **보이는 모양만 바꾸는 것**이 있다. 둘을 섞으면 과금과 UX가 모두 틀어진다.

| 설정 | 분류 | 나중에 바꿀 때 |
|---|---|---|
| 템플릿 | 모양 | **재렌더만. 무료.** 몇 번이든 교체 가능 |
| 자막 스타일·위치·폰트 | 모양 | 재렌더만. 무료 |
| 제목 문구 | 모양 | 재렌더만. 무료 |
| 장르 | **컷** | 재분석 → 크레딧 재차감 |
| 클립 길이 | **컷** | 재분석 → 크레딧 재차감 |
| 변환 구간 | **컷** | 재분석 → 크레딧 재차감 |

**UI 규칙:** 모양 설정에는 "무료 · 바로 반영" 배지를 붙인다. 컷 설정을 바꾸는 동작에는 버튼 라벨 안에 비용을 적는다 — "다르게 다시 찾기 · 100 크레딧". 사용자가 누르기 전에 어느 쪽이 돈 드는지 알아야 한다.

**구현 함의:** 렌더 스펙(템플릿)과 컷 결정(하이라이트 구간)을 데이터 모델에서 분리해야 한다. 지금 `clips` 테이블은 둘이 섞여 있으므로, 하이라이트 구간은 유지한 채 렌더만 다시 돌릴 수 있는 경로가 필요하다.

## 4. 장르 자동 추론

사용자에게 묻지 않고 추론한다. 입력은 이미 확보되어 있다 — 영상 제목, 채널명, 전사(transcript). 전사는 어차피 읽으므로 추가 비용이 거의 없다.

추론 결과는 **숨기지 않는다.** 두 군데에서 고지한다.

1. 변환 중 화면: "강연·인터뷰로 보고 장면을 찾고 있어요"
2. 결과 화면 상단 판단 바: 장르 + **왜 그렇게 봤는지 한 문장** + 적용된 구간·길이

예시 문구:
> 강연·인터뷰로 보고 8개를 찾았어요. 말이 느리고 한 사람이 길게 설명하는 구조라, 주장과 숫자가 나오는 지점을 기준으로 잘랐습니다. 전체 구간 · 길이 자동.

장르 목록과 각 장르의 선별 기준:

| 장르 | 무엇을 좋은 장면으로 보는가 |
|---|---|
| 강연·인터뷰 | 핵심 주장과 숫자가 나오는 지점, 질문을 던지고 답하는 구간 |
| 예능·리액션 | 웃음과 리액션이 터지는 순간, 말이 겹치고 빨라지는 구간 |
| 정보·뉴스 | 결론을 먼저 말하는 지점, 수치·비교가 나오는 구간 |
| 리뷰·상품 | 장단점을 말하는 지점, 가격·결론 구간 |
| 브이로그·일상 | 장면 전환 지점, 분위기가 올라오는 구간 |

이 기준은 하이라이트 추천 프롬프트(`highlight_service.py`)에 장르별 분기로 들어간다.

## 5. 클립 생성 개수

**6~8개를 생성한다.** 2~3개는 적다.

요금이 원본 길이 기준 구간제라면 출력 개수와 과금이 무관하므로, 적게 주는 건 사용자 손해다. 게다가 2~3개 중 쓸 만한 게 없으면 재분석해야 하고 거기서 크레딧이 또 나간다. 점수순 정렬이 기본이므로 많이 줘도 고르는 부담은 늘지 않는다.

서버 원가가 문제라면 개수가 아니라 **분석 모델 선택**으로 조정한다. 실제 원가는 거기서 나간다.

## 6. 템플릿 스키마 (9축)

템플릿을 평면적인 프리셋 딕셔너리가 아니라 **구조화된 스펙**으로 재설계한다. 현재 `visual_style_catalog.py`는 제목·부제·자막의 x/y/fontSize/color만 담고 있어 피카클립 수준에 도달할 수 없다.

축:

1. **레이어** — 요소들의 z 순서와 표시 여부
2. **레이아웃** — 비율(16:9 / 4:3 / 1:1 / 9:16 / Dual)과 화면 스타일(단색 / 글래스 / 이미지)
3. **제목** — 줄 수, 폰트, 크기, 자간, 행간, 정렬, 배경, 그림자(색·높이·블러·각도·강도), 외곽선(다중 레이어), 위치
4. **자막** — 위 항목 전부에 더해 **모션 프리셋**과 **적용 범위**(단어 / 줄 / 구간)
5. **텍스트** — 고정 텍스트 요소
6. **이미지** — 고정 이미지 요소
7. **로고/CTA** — 브랜드 마크와 위치
8. **아웃트로** — 끝에 붙는 영상
9. **음원** — 배경 음악

### 자막 모션 프리셋 — 8종 (확정)

기존 `ALLOWED_CAPTION_ANIMATIONS`는 `none`, `highlight` 2종뿐이었다. 12종으로 만들어 전부 렌더해본 뒤 **8종으로 확정**했다.

```text
효과 없음 · 팝 · 박스 하이라이팅 · 페이드 인
엘리베이트 · 카라오케 · 네온사인 · 타자기
```

**뺀 4종과 이유** (2026-10-12, `remotion/out/motions/` 렌더 확인):

| 뺀 것 | 이유 |
|---|---|
| 바운스 | 팝과 구분되지 않음. 18px 튀어오르는 변형이 0.2초면 끝나고 색 변화만 읽힘 |
| 슬라이드 업 | 페이드 인과 같은 이유로 중복 |
| 팝 그룹 | 줄 등장 시 1회만 움직이고 이후 정지. 자막은 말하는 내내 화면에 있으므로 사실상 "효과 없음" |
| 박스 라인 | 같은 구조. 박스가 남는 만큼 팝 그룹보다 낫지만 움직임은 역시 1회뿐 |

줄 단위 모션을 넣는다면 **말하는 단어를 따라 강조가 이동**해야 한다. 그건 위 두 개를 손보는 게 아니라 새 설계다. 지금은 줄 단위 모션이 하나도 없으므로 `GROUP_MOTIONS` 개념 자체를 코드에서 제거했다.

저장된 행이 뺀 값을 들고 있으면 `pop`으로 정규화된다.

### 스키마를 먼저 확정할 것

템플릿 15~20종을 만든 뒤에 스키마를 바꾸면 전부 다시 만들어야 한다. **스키마 확정 → 모션 엔진 → 템플릿 제작** 순서를 지킨다.

### 기본 제공 템플릿

15~20종. 장르별로 묶는다(강연·예능·정보·리뷰·브이로그). 규칙:

- 이름은 번호가 아니라 쓰임으로 — "추천 스타일 13"이 아니라 "강연 · 큰 자막"
- 미리보기는 정지 이미지가 아니라 **짧은 반복 재생**. 사용자가 고르는 기준이 모션이므로 정지 이미지로는 고를 수 없다
- 모든 템플릿의 미리보기는 **같은 문구와 같은 배경**으로 만든다. 다르면 사용자가 템플릿이 아니라 배경을 비교하게 된다
- "직접 만들기" 타일은 목록 **앞**에 둔다

### 테마 규칙

밝은 테마는 관리 화면(목록·갤러리·결과), 어두운 테마는 작업 화면(홈 입력부·변환 중·편집기). 테마 토글이 아니라 **화면의 성격**이 테마를 정한다. 에디터를 밝게 그리지 않는다 — 9:16 프리뷰 주변이 밝으면 영상의 실제 밝기를 판단할 수 없다.

## 8. UI 문구 규칙

- 버튼은 하는 일을 그대로 적고, 끝나면 같은 말로 알린다 ("내보내기" → "내보냈어요")
- 기술 용어를 쓰지 않는다 — "렌더 큐 등록"이 아니라 "변환 시작", "ASS 자막 번인"이 아니라 "자막 입히기"
- 오류는 사과하지 말고 무엇이 잘못됐고 뭘 하면 되는지 적는다 — "오류가 발생했습니다" 대신 "120분을 넘는 영상은 변환할 수 없어요. 구간을 나눠서 올려주세요"
- 크레딧이 드는 동작은 버튼 라벨에 숫자를 넣는다
- 숫자(타임코드·크레딧·점수·길이)는 모노스페이스에 tabular-nums. 목록에서 자릿수가 세로로 맞아야 비교된다

### 실제로 바뀐 것 — ASS 번인 제거 (2026-10-12)

"두 파이프라인 통합"을 조사해 보니 영상 클리핑 경로는 **이미 Remotion으로 렌더**되고 있었다(`clip_service.render_clip_with_template` → `render_blog_shorts_with_remotion`). 모션 자막을 막고 있던 건 그 앞 단계였다 — FFmpeg가 ASS 자막을 소스 MP4에 **픽셀로 구워 넣은** 뒤 Remotion이 그 영상을 감싸고 있었다. 이미 그림이 된 글자에는 모션을 줄 수 없다.

그래서 통합은 렌더러 교체가 아니라 **번인 제거**였다.

| 바뀐 것 | 내용 |
|---|---|
| `clip_service` | v1 템플릿 렌더는 ASS를 굽지 않는다. 레거시 `visual_style`은 그대로 굽는다 — 모션이 없으니 잃을 것도 없고, 기존 출력이 달라지면 안 되기 때문 |
| `clip_service` | v1 렌더는 소스로 `subtitled_output_path`를 쓰지 않는다. 전에 레거시로 렌더한 클립은 자막이 구워진 파일이 남아 있어, 그걸 쓰면 같은 말이 두 번 겹친다 |
| `caption_timeline.py` (신규) | 전사 구간 → `captionLines`. 클립 시작 기준 상대 시간, 겹침 없음, 0.35초보다 짧은 줄은 다음 줄에 합침(깜빡임 방지). 단어 타임스탬프가 없으면 구간 단위로 떨어짐 |
| `BlogShorts.tsx` | 장면이 `captionLines`를 들고 있으면 줄마다 중첩 Sequence로 그린다. 미디어 Sequence는 형제이므로 영상은 끊기지 않고 이어진다 |

**렌더해서 잡은 버그:** 중첩 Sequence는 프레임 0을 그 줄의 시작으로 바꾼다. word 타이밍은 장면 기준이었으므로, 첫 줄만 정상이고 둘째 줄부터는 강조가 줄 끝을 넘어간 지점을 가리켜 **아무 단어도 강조되지 않았다**. 1번 줄이 완벽해 보여서 코드만 읽었으면 놓쳤을 버그다. 줄 Sequence를 만드는 쪽에서 시간을 옮겼으니 같은 자리에서 되돌린다.

`npm run smoke-caption-lines` — 4줄짜리 고정 입력을 렌더한다. 이 버그를 잡는 가장 작은 크기다(한 줄이면 안 잡힌다). Chrome을 내려받을 수 없는 환경에서는 `REMOTION_BROWSER_EXECUTABLE`로 기존 Chromium을 지정한다.

**아직 남은 것:** `template_bridge`가 9축 중 일부를 버린다(제목 외곽선 다중 레이어, 고정 텍스트·이미지, 브랜드, 아웃트로, 음원). 7번 편집기는 **렌더러가 반영하는 축만** 노출해야 한다 — 버려지는 축에 UI를 붙이면 사용자가 만진 설정이 결과에 안 나타난다.

---

**렌더 확인 완료:** 12종을 전부 렌더해 보고 8종으로 정리했다(위 표). 샘플은 `remotion/out/motions/`에 있고 `npm run smoke-motions`로 다시 뽑을 수 있다. 템플릿 18종의 모션 배정도 8종 기준으로 다시 맞췄다.

**레거시 호환:** 저장된 `captionAnimation: "highlight"`는 `pop`으로 매핑된다. 이름과 달리 옛 렌더러가 실제로 그린 것이 박스가 아니라 색 변화 + 확대였기 때문. `template_schema.py`와 `BlogShorts.tsx` 양쪽을 같은 값으로 맞춰야 하며, 어긋나면 기존 클립이 전부 다른 모양으로 렌더된다.

0~2번이 기반이다. 여기를 건너뛰고 화면부터 만들면 같은 문제가 반복된다.

## 10. 미확정 항목

- **클립 편집기 MVP 범위.** 자막 문구 수정과 구간 앞뒤 조정까지만 할지, 타임라인·요소·전환효과까지 갈지. 편집기는 전체 개발 난이도의 절반 이상을 차지하므로 여기서 범위를 잘못 잡으면 다시 지친다. 결과 화면에서 템플릿을 무료로 바꿀 수 있게 되면서 편집기의 부담이 줄었다는 점을 고려할 것.
- **요금제와 크레딧 단가.** 구간제로 간다는 방향만 정해졌고 실제 숫자는 미정. 원가 실측이 먼저다.
- **유튜브 링크 입력의 약관·저작권 처리.** 초기에는 파일 업로드만 받는 쪽이 안전할 수 있음.
- **클립 개수 상한과 분석 모델 선택.** 6~8개 방침은 정해졌으나 모델별 원가 실측이 필요.

## 11. 참고 — 피카클립 과금 구조

우리 요금을 정할 때의 **참고치**이며 우리 정책이 아니다. 2026-10-08 확인.

영상 변환은 원본 길이 기준 구간제이고 출력 클립 수와 무관하다. 5분 이하 50C / 5–30분 100C / 30–60분 200C / 60–90분 300C / 90–120분 400C / 120분 초과 미지원. 실패한 작업은 자동 환원.

요금제: 라이트 5,500원(500C) / 크리에이터 7,900원(1,500C) / 프로 20,000원(5,000C) / 엔터프라이즈 문의.

기능별 차감: AI 이미지 2~100C, AI 영상 180~360C, 다국어 숏폼 100C/국가, 썸네일 50C, 자동 레이아웃 10C, 부분 자막 재생성 2C/세그먼트, TTS 1~2C, 효과음 10C, 업로드 10C, 무음 구간 제거 무료.

**가져온 것:** 구간제 과금, 변환 버튼에 비용 명시, 실패 시 환원, 점수와 근거를 함께 보여주는 구조.
**다르게 간 것:** 소스 단일 입력, 장르 자동 추론과 근거 고지, 템플릿을 변환 후 무료 교체, 템플릿 이름을 쓰임 기반으로, 점수 근거를 레이더가 아닌 막대로.

## 12. 구현 후 남은 결정 (2026-10-12)

0~8번을 구현하면서 **제품 판단이 필요해 코드로 정하지 않은 것**들이다. 각 항목에 지금 코드가 어떻게 동작하는지 적었으므로, 결정이 나면 고칠 자리는 한 곳이다.

### 12.1 과금 단위 — 변환 횟수 vs 크레딧 (가장 큰 것)

지금 `users.monthly_usage` / `usage_limit`은 **월 변환 횟수**다. §11에서 참고한 구간제는 **크레딧**이다. `credit_service.cost_for_duration()`은 구간제로 정확한 값을 계산하지만, 실제 차감은 여전히 "1회"다.

| | 지금 | 구간제로 가면 |
|---|---|---|
| 저장값 | 변환 횟수 | 월 크레딧 |
| 5분 영상 | 1회 | 50C |
| 2시간 영상 | 1회 | 400C |
| 요금제 정의 | `monthly_video_limit` | `monthly_credits` |

**결정해야 할 것:** 미터를 크레딧으로 바꾸는가. 바꾸면 기존 사용자의 잔량을 환산해야 하고(마이그레이션), 요금제 의미가 전부 달라진다. 되돌리기 어려우므로 코드로 밀지 않았다.

**결정 전까지의 동작:** 화면에는 구간제 금액을 **정확히 보여주고**(`/videos/credit-quote`), 실제 차감은 1회로 한다. 즉 지금은 고지와 차감이 다르다 — 이 상태로 출시하면 안 된다.

### 12.2 요금 숫자

`credit_service._PROVISIONAL_TIERS`는 **피카클립의 공개 표**를 자리만 채워둔 것이다. 우리 정책이 아니며 이대로 출시하면 안 된다. 원가 실측(§10)이 끝나면 **이 표만** 바꾼다 — 가격을 아는 코드는 이 모듈뿐이다.

### 12.3 템플릿 편집기가 못 건드리는 축

`template_schema.EDITABLE_PATHS`가 편집기에 노출되는 축이고, `template_bridge.DROPPED_IN_BRIDGE`가 렌더러가 버리는 축이다. 지금 편집할 수 있는 것은 8개뿐이다 — 비율, 배경색, 영상 채우기, 제목 색, 자막 효과·색·강조색·배경.

버려지는 축(제목 크기·외곽선·그림자·위치, 자막 크기·위치·범위, 고정 텍스트·이미지, 로고/CTA, 아웃트로, 음원)은 **컨트롤을 만들지 않고 화면에 "아직 못 바꾸는 것"으로 고지**한다. 만질 수 있는데 결과에 안 나타나는 것보다 낫다.

**결정해야 할 것:** 이 축들을 렌더러에 실을 순서. 9축을 다 실으려면 `BlogShorts.tsx`가 템플릿 스펙을 직접 받는 구조로 가야 하고(현재는 `remotion_style_payload` 형태의 평면 딕셔너리), 그건 블로그 경로 렌더까지 건드린다. 편집기 UI는 백엔드의 `/video-templates/editable`을 읽으므로, **렌더러가 축을 더 반영하면 프런트 수정 없이 컨트롤이 늘어난다.**

### 12.4 내 템플릿 저장

갤러리의 "내 템플릿"은 아직 없다. 지금 조정값은 렌더 1회에만 적용되고 저장되지 않는다 — 템플릿을 바꾸면 그 템플릿의 기본값에서 다시 시작한다. 저장을 넣으려면 테이블과 CRUD가 필요하고, 그건 §12.3의 축 범위가 정해진 뒤가 낫다. 지금 저장하면 나중에 못 쓰는 축이 담긴 데이터가 쌓인다.

### 12.5 장르를 직접 골라 다시 찾기

`POST /videos/{id}/reanalyze`는 `genre`를 받지만 화면에는 장르 선택이 없다. 버튼은 "같은 조건으로 다시"만 한다. 장르 칩은 편집기의 컷 설정 묶음에 같이 넣는 게 맞고, 그 묶음에는 클립 길이·변환 구간도 들어간다 — 셋 다 재분석·재차감이므로 한자리에 모여야 한다.

> 결정(2026-10-13): 결과 "프로젝트 허브"는 없앴다. 변환이 끝나면 곧바로 3단 편집기로 가고, 편집기를 닫으면 프로젝트 목록으로 간다.
